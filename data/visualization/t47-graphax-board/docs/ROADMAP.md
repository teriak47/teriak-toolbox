# Graphax roadmap

Proposed work on Graphax, grouped as fixes, optimisations, visual improvements and new features. Each item is done as its own change and validated before the next one starts.

Effort: **S** small, **M** medium, **L** large.

## 1. Fixes

| ID | Status | Issue | Where | Severity | Effort |
|---|---|---|---|---|---|
| C1 | Done | The Delete key removed the selected node or link at once, with no confirmation and no undo. It now asks first (Enter or Delete again confirms, Escape cancels); Backspace works the same way. | `src/components/GraphCanvas.tsx` | High | S |
| C2 | Done | Project import, project deletion and category deletion ran several statements without a transaction, so a failure part-way could leave a half-imported project, orphan nodes or stale category references. Project creation, the demo, import and every deletion now run in a single transaction. | `server/bulk.ts`, `server/routes/*.ts` | High | M |
| C3 | Done | The API did not check that the project, nodes or category existed before creating a category, node or link, nor that both ends of a link belonged to the same project; a batch position update could also move another project's nodes. These references are now checked (404 for a missing project, 400 for an invalid node or category). | `server/guards.ts`, `server/routes/*.ts` | Medium | M |
| C4 | Done | Input validation was thin: `color`, `icon` and `shape` accepted any string, requests had no size limit, malformed JSON returned 500 instead of 400, and fields of the wrong type could crash a route. Category styles are now validated (`#rgb` is stored as `#rrggbb`), requests are limited to 2 MB (50 MB for an import), malformed or non-object JSON returns 400, and imports skip or default invalid entries. | `server/validation.ts`, `server/routes/*.ts`, `server/app.ts` | Medium | S |
| C5 | Done | Category defaults disagreed (`mapCategory` used `rounded` / `#38bdf8`, presets `sharp` / `#47c0ef`, import `rounded`), and `normalizeCategoryRecord` was an unused duplicate. Defaults now come from one place in `shared/types.ts` (`#47c0ef`, `tag`, `sharp`), stored records with unknown values are read with these defaults, and the duplicate is removed. | `shared/types.ts`, `server/mappers.ts`, `server/presets.ts` | Low | S |
| C6 | Done | Exporting from the workspace had no error handling, so a failure went unnoticed, and an edit typed just before or still being saved could be missing from the file. The export now waits for the inspector's typing delay and for saves in flight, reports a failure, warns when some edits are not saved, and shares its code with the dashboard (file names keep accented letters readable). | `src/lib/exportProject.ts`, `src/components/Workspace.tsx` | Low | S |
| C7 | Done | The French README described the canvas as React Flow while it is a custom SVG renderer, and `@xyflow/react` and `tsx` were unused dependencies. Both READMEs now describe the actual architecture and the two packages are removed. `@surrealdb/node-native` is kept: it is a required peer dependency of `@surrealdb/node`. | `README*.md`, `package.json` | Low | S |

## 2. Optimisations

| ID | Status | Topic | Finding | Benefit | Effort |
|---|---|---|---|---|---|
| O1 | Done | Live physics | The loop never stopped once the graph settled, re-rendered the whole SVG on every frame and saved every node position every 1.8 s. It now goes to sleep when the graph is still (no DOM updates at rest), wakes when a node is dragged or the links change, and saves only the nodes that moved, when the graph settles or at most every 5 s while it moves. On the demo, 12 s of physics went from 8 saves of all nodes to 2. The repulsion now switches to a Barnes-Hut quadtree (O(n log n)) above 1,000 nodes, where it is faster than the exact sum (3,000 nodes: about 28 ms → 12 ms per frame, error under 5 % against the exact forces, unit tested); smaller graphs keep the exact sum. Measured on a 600-node graph, the frame rate is limited by rendering the SVG, not by the forces. | CPU and battery use, fewer writes | M |
| O2 | Done | Batch positions | The server ran one query per node, sequentially; it now updates them in one transaction (done with C3). | Faster layouts | S |
| O3 | Done | Project list | Counting loaded every category, node and link record; counts now come from `GROUP BY` with `count()` in the database. Measured on 4 projects with 20,000 nodes and 20,000 links: about 30 % faster (≈250 ms to ≈175 ms), since SurrealDB still scans the rows but no longer returns them. | Faster dashboard with large databases | S |
| O4 | Done | Create, demo, import | Records were created one at a time; they are now written with batched inserts in one transaction (done with C2). | Speed and atomicity | S |
| O5 | Done | Bundle size | The client bundle was 562 kB in one file. The workspace, the Markdown preview (`react-markdown`, `remark-gfm`) and `dagre` are now loaded on demand: the initial bundle is 275 kB (86 kB gzipped, from 173 kB), and the build no longer warns about chunk size. | Faster start | S |
| O6 | Done | Large components | `GraphCanvas.tsx` (1,909 lines) and `Workspace.tsx` (1,321) mixed state, persistence, camera, physics and geometry. Extracted: `useSaveQueue` (save tracking and retry), `useViewport` (camera, wheel zoom, coordinate conversions), `usePhysicsSimulation` (live layout), and the pure `canvasGeometry` and `edgeGeometry` modules, now unit tested. The canvas markup is now split into presentational components in `src/components/canvas/`: `NodeView`, `EdgeView` (memoised), `MiniMap`, `CanvasDock`, `NodeCategoryMenu`, `DeleteConfirmBar` and `ShapeOutline`; `GraphCanvas` keeps the state and the pointer logic and passes it as callbacks. The SVG drawn is unchanged (the exported picture of the demo is byte for byte the same size). `GraphCanvas.tsx` went from about 2,000 lines to about 1,390. | Maintainability, testable code | L |

## 3. Visual improvements

| ID | Status | Topic | Proposal | Effort |
|---|---|---|---|---|
| V1 | Done | Node shapes | Only square and cut-corner boxes were drawn (legacy `rounded` and `pill` fall back to squares). Hexagon, diamond, octagon and circle are added, sized to carry the same visual weight as the square. Links end exactly on every outline (ray and polygon intersection, unit tested for each shape and direction), halos and selection rings follow the shape, and the category editor shows each shape and a live preview of the node. | M |
| V2 | Done | Link colours | Links took a single colour. A link can now have its own colour, picked in the inspector from eight hues sharing the accent blue's lightness and chroma, or reset to the default grey. The colour is stored as `#rrggbb`, validated by the API, kept through reversal and export/import, and used for the link, its arrows and its label frame; a selected node's direction colours (V3) take precedence. Link types: each colour (and the default grey) can be given a name in the new "Types de liens" sidebar section, saved on the project (`linkTypes`, replaced as a whole on `PATCH /api/projects/:id`, kept through export and import); the inspector shows the type of the selected link. A click on a type shows only its links, and a link created meanwhile takes that colour. | M |
| V3 | Done | Link direction | The arrowhead was small and sat on the target border. Arrowheads are larger, every directed link has a second arrow along it (moved towards the source when the middle holds the label), moving dashes show the direction of hovered or selected links, and when a node is selected its outgoing links are drawn in the accent blue and its incoming links in a matching lavender (new `--lien-sortant` and `--lien-entrant` tokens), with a legend giving both counts. The dash animation is disabled when the system asks for reduced motion. | M |
| V5 | Done | Categories | The preset category sets are reviewed: the former "OSINT & Cyber" set is split into an OSINT investigation set (person, organisation, online account, contact, place, event, document, hypothesis) and a Cyber / CTI set, colours no longer repeat within a set, shapes follow one meaning across sets (circle person, hexagon technical, octagon threat or risk, diamond uncertain, cut corner evidence, square the rest), two icons are added (`@`, phone), and categories keep their order (new ones go last). Categories can be reordered by drag and drop (or arrow keys) in the sidebar; a right click on a node opens a menu to change its category (adding the new category's default keys); the category editor lists the nodes that will become unclassified before a deletion. A category can be merged into another one from its editor: its nodes move to the target, which gets the default keys it lacks, and the source is deleted, in one transaction (`POST /api/categories/:id/merge`), undone in one step. A project's categories can be saved as a preset (bookmark button above the category list, stored in the database) and picked under "Mes presets" when creating a project, where a preset can also be deleted. | M |
| V6 | Done | Metadata | Metadata were plain key/value text fields. The inspector now suggests keys already used in the project, recognises value types (URL, e-mail, IPv4/IPv6, date, MD5/SHA-1/SHA-256/SHA-512, number, including defanged values), warns when a value does not fit its key (for example a date that is not a date), opens plain URLs in a new tab (defanged URLs are never linked) and copies values. The search accepts `Clé:valeur` and `Clé:` (empty fields never match). Each category can list up to 12 default keys, added empty to its new nodes and to nodes moved into it, and up to 2 of them are shown under the node title; the inspector offers a node's missing keys, and the preset categories come with their own keys. | M |
| V4 | Done | Views | Beyond the free canvas, the workspace now offers: the neighbourhood of a node, 1 to 3 links away (focus button in the inspector); the shortest path between two selected nodes (multiple selection panel); a table view of the shown nodes and links, sortable, a click selecting the row in the inspector; a timeline of every dated attribute of the shown nodes (`YYYY-MM-DD[ HH:MM]` or `DD/MM/YYYY`), grouped by day; a grouped layout, one column per category; and saved views. A saved view keeps the hidden categories, the link filters, the neighbourhood, the view mode and the framing under a name; views are stored on the project (`savedViews`) and follow the new ids through import, duplication and snapshots. The pure logic is unit tested (`tests/graphViews.test.ts`). Absorbs A4 and A5. | Read a large graph from several angles | L |

## 4. New features

| ID | Status | Feature | Why | Effort |
|---|---|---|---|---|
| A1 | Done | Undo and redo: buttons in the toolbar, `Ctrl+Z` and `Ctrl+Y` (or `Ctrl+Shift+Z`) outside text fields. Undoable: moving a node, automatic layouts, a node's title, notes, category and attributes, a link's label, style, orientation, colour and notes, reversing a link, the category order, a category's edits, and creating or deleting a node (with its links), a link or a category. Deleted records come back with their ids through `POST /api/projects/:id/restore`; a deleted category goes back to its place and to the nodes that have not got another one since. Typing in a field is undone as one edit; the tooltip names the action. | The missing safety net, and the natural follow-up to C1 | M |
| A2 | Done | Multiple selection: Ctrl+click (Cmd on Mac) adds or removes a node, Shift+drag on the background selects the nodes inside a box, Escape clears it. Dragging a selected node moves the whole group, saved and undone as one step. Delete (with confirmation) or the side panel removes the selected nodes and their links in one request (`POST /api/projects/:id/nodes/delete`), undone as one step. The side panel lists the selection by category. Shift+click was already taken by linking, hence Ctrl+click. | Needed once a graph grows | M |
| A3 | Done | A dedicated reliability field: the Admiralty code, a source reliability A–F and an information credibility 1–6 (e.g. `B2`), picked from two lists in the inspector, validated by the API, kept through export, import, undo and restore, and shown as a badge on the node's corner with its meaning in the tooltip. It is searchable like an attribute (`Fiabilité:B2`, `fiabilite:a`). The demo and the presets now use the field instead of a free "Fiabilité" attribute. | The demo already stores it in free metadata | S |
| A4 | Moved to V4 | Neighbourhood focus and shortest path | | |
| A5 | Moved to V4 | Timeline view | | |
| A6 | Done | The "Exporter" menu saves the project as JSON (as before), a Markdown report (nodes grouped by category with their reliability, attributes and notes, then a table of the links; `src/lib/report.ts`, unit tested), or a picture of the whole graph as SVG or PNG (2×). The picture is framed on the graph, not on the screen, without the selection; the canvas styles (CSS variables and classes) are written on each element so the file looks the same outside the app. | Sharing and delivering an investigation | M |
| A7 | Done | Project snapshots: the server writes a project's export bundle to `data/snapshots/<project id>/` automatically every 30 minutes when the project changed (`GRAPHAX_AUTO_SNAPSHOT_MINUTES`, `0` turns it off; the 10 latest are kept), and on demand from the "Instantanés" window (up to 50 kept). A snapshot is restored as a new project, leaving the current one untouched, and can be deleted. The files use the export format, so they can also be imported from the project list, even after the project was deleted. The export and import code moved to `server/bundles.ts`, shared by both. | The README asks users to keep backups; the tool could do it | S |
| A8 | Done | A project can be duplicated from its card on the project list ("<name> (copie)", new ids, one transaction, `POST /api/projects/:id/duplicate`). `Ctrl+C` copies the selected node or nodes with the links between them, and `Ctrl+V` pastes copies a little to the side, also into another project (categories are then matched by name); a paste is one request through the restore route and is undone in one step. The copy is kept in the browser's storage. | Everyday convenience | S |
| A9 | Done | Browser tests of the workspace (`tests/e2e/`, Playwright driven by `node --test`, as the other tests): they start the built app on a throwaway database and check the demo graph and its badges, creating a node with undo and redo, moving a multiple selection with one-step undo, deleting a node with its confirmation and restoring it with its links, and the right-click category menu. `pnpm test:e2e`; the Graphax CI workflow installs Chromium and runs them after the build. The pure front-end logic was already unit tested with `node --test`, so Vitest was not added. | Only the API is tested today | M |
| A10 | Done | Desktop app and Rust API: Graphax runs as a Tauri 2 desktop app (installers for Windows, macOS and Linux built on release tags) that embeds the interface and the API. The Node + Hono server is replaced by a Rust API (`api/`, axum and embedded SurrealDB 3.3, the same database format, so existing projects open as they are), which also serves the interface in browser mode (`pnpm start`). Every route was ported with the same behaviour: the HTTP cases of `tests/api.test.ts` run against it, and its own tests cover what they checked in the database. The app keeps its data in its own folder, takes automatic snapshots, closes the database cleanly on exit, and brings its window to the front when opened twice. | Launch Graphax without Node.js, pnpm or a terminal | L |

## Suggested order

1. **Data safety:** C1, C2 with O4, C3, C4.
2. **Clean-up and performance:** C5, C6, C7, O1, O2, O3, O5.
3. **Readability and ease of use:** V3, V2, V1, V5, V6.
4. **Larger features:** A1, A2, A3.
5. **Later:** O6, then V4, A6 to A9.
